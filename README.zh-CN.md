# Sparkle

_一个同事式 Agent。_

[English](./README.md)

Sparkle 不是一个聊天机器人，她是一名**一直在岗的 AI 员工**。

大多数「AI 助手」都在等：你打字，它回答，然后继续睡。Sparkle 不等你。资讯源更新了一篇值得知道的文章，她会醒；待办到点了，她会醒；定时器触发，她会醒；有时候——手头安静下来，她也会自己醒来，看看有什么值得做的。回答问题只是她工作的一部分，而不是她本身。没有人会把自己的岗位描述写成「回答问题」。

整个项目就是一句话：

> **Agent as a colleague.**

## 她的工作方式

- **接任务、交付、汇报。** 你交代的事她记着、跟进、给结果；做不了或做砸了，她直说。
- **有主动性。** 发现值得做的事，她可以直接去做，也可以先向雇主提议——不必等指令。
- **她读资讯。** 盯着信息源，替你筛出值得知道的动态。
- **她上真实的网。** 丢给她一个链接、一个问题，她会打开浏览器自己去查。
- **她跑命令、记待办、查地图**——空闲的时候，时间由她自己安排：盘点待办、跟进挂起的事，或做点她判断值得做的事。

这些都不是「给聊天机器人加的功能」。每次要加点新东西，我们问的从来不是「用户会想要什么功能」，而是——**「这是给这名员工添了一种新的工作能力吗？」**

## 她如何运转

把 Sparkle 的工作环境想象成一台手机，把 Sparkle 这个 Agent 想象成拿着手机的人。

- **每一种输入都是平级的事件。** 一条消息、一篇新闻、一个定时器、一个系统信号——一律平等。没有高人一等的「用户消息」，消息渠道只是众多 App 里的一个。
- **后台信号以横幅的形式到达。** 一个统一的通知中心把它们聚合、窗口化，再唤醒她。她正盯着的那个会话则像已经打开的屏幕——新消息直接刷进来，不必等横幅。
- **她的能力是一个个能走进去的 App。** 资讯阅读器、浏览器、终端、待办、地图。她进去，做完事，再走出来。

另外有一个小小的管理台：一扇安静的窗，能看到她的工作状态——最近在想什么、做什么、看到了什么。

> 她的长期记忆走「自维护工作笔记」的方向。目前她保留一份原始的消息账本，并在同一段上下文里记事。

## 把她跑起来

Sparkle 是一个全栈 TypeScript Monorepo（`pnpm`）。在底层，她不是一个程序，而是一组协作的独立进程——她本体，加上一个浏览器、一个对象存储、一个 LLM 网关等等——统一由 PM2 托管。一条命令就能把整套拉起来。

你需要准备：

- Node.js 和 `pnpm`，以及一套能编译原生模块（`better-sqlite3`）的工具链——数据库就是一个进程内的 SQLite 文件，不用另外跑外部数据库。
- 一个你能登录的 LLM。

然后：

```bash
# 1. 配置
#    config.yaml（非隐私，已在仓库里）——直接改。
#    复制隐私模板，填入你的密钥：
cp config.secret.yaml.example config.secret.yaml

# 2. 装依赖并把她拉起来（构建 → 迁移 → 由 PM2 启动）
pnpm install
pnpm app:deploy
```

这就是最短路径。跑完，她就在岗了。
